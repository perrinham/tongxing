### 过程中踩的坑（都是自己写的）

1. **高德 key 不该进库 → 挪进 `.env.local`，当场引爆一个回归**：
   `config.ts` 改读 `import.meta.env.VITE_AMAP_WEB_KEY` 后，三个 esbuild 打包的冒烟全崩——
   **esbuild 环境里没有 `import.meta.env`**，`import.meta.env.VITE_…` 直接 `TypeError: Cannot read properties of undefined`。
   修法：`import.meta.env?.VITE_…` 可选链 + 回退 `globalThis.process.env`（浏览器构建里 Vite 已把字面量烤进去，回退走不到）。
   另用一个小实验确认：**esbuild 的 `define` 支持 `import.meta.env.VITE_X` 整路径**（打包时替换成字面量）。
2. **T 空 key 时 amap 会真崩/降级歧义** → `scripts/lib/env.mjs` 的 `loadEnvLocal()` 从 `.env.local` 读 VITE_ 前缀
   注入 `process.env`，`amap-itin-test.mjs` 启动时调用一次，让打真高德那段有 key 用。
3. **`fix-env.mjs` 第一个能跑的版本就是坏的**：
   ① `node <esbuild-native-binary> --version` 把 Mach-O 二进制当 JS 跑，SyntaxError；
   esbuild 的 `bin/esbuild` 是**原生二进制**只能直接执行。
   ② 补齐平台包时用 `copyFileSync` 逐文件拷，遇到目录结构 `EISDIR`；
   改 `cpSync(src, dest, { recursive: true })`。作为「环境自检脚本」第一版就跑出真缺陷，算是把「审计脚本自己也要被证伪」这条用在了自己身上。
4. **`server/smoke.mjs` 早已有一个 `const H`**（hardened 实例请求助手），harness 变量撞名 → 模块级 `SyntaxError: Identifier 'H' has already been declared`。
   改名 `T`。这类「模块里已有一个通用单字母名」以后先 grep 再定名。
5. **C2 的边界要画清楚**：Node 版冒烟里未捕获异常 / 未处理 Promise 拒绝 **默认就让进程非零退出**（Node ≥15 行为），
   不需要 harness 再造一遍；UI 侧运行时错误另有 `[app-err:…]` 前缀兜住可见性。

### B3 的有意取舍：server/smoke.mjs 不拆文件

原计划「2277 行按 [1]–[18] 拆成 18 个模块」。勘察后发现 sections 是**顺序共享状态**的：
前面的 section 建的服务实例 / 空间 / 令牌被后面的断言引用。拆文件要么造一套不可靠的 fixture 注入、
要么破坏既有行为，纯赔本。改为：四段冒烟统一走同一份 harness 契约（B2），
断言宏不再是四处各写各的，维护成本从「漂移四份」降为「一份契约」。
