## 旅游 H5 小程序 —— 实现计划

- 需求：旅游 H5 小程序，用户选定方向为「AI 行程规划（1）+ 同行 AA 记账（4）」结合。
- 产品内核定为：**一次旅行 = 一个共享 Trip 空间**，行程与账单共用同一组成员，不拆成两个独立工具。
- 技术选型：uni-app（Vue3 + Vite + TS）→ 一套代码出 H5 + 微信小程序；MVP 纯前端本地存储，不依赖登录与后端；数据层封装 repository，后端可插拔。
- 数据模型：Trip / Member / Day / ItineraryItem / Expense（payerId + participants，三种分摊模式）/ Settlement（计算产物）。
- 页面结构：4 Tab —— 行程（时间轴卡片流）、记账（流水 + 人均统计）、结算（谁欠谁 + 最少转账）、我的（空间管理）。
- 两个核心算法：① AI 行程生成 MVP 用模板 + 规则引擎（Phase 2 换 LLM，同数据结构）；② AA 结算用贪心配对法压到 ≤ n−1 笔转账。
- 里程碑：M1 骨架 → M2 行程 → M3 记账 → M4 结算 → M5 打磨（M1–M4 为可演示核心）。
- 交付物：PLAN.md（实现计划，已写入工作区根目录，待用户确认后进入开发）。

## 旅游 H5 小程序 —— 代码实现完成（M1–M4）

**交付**：`/Users/a1111/WorkBuddy/2026-09-16-11-50-05`，30 个源文件、约 7670 行，`npm run dev` 即跑。

**技术栈实测决策（与原计划偏差）**：计划写的是 uni-app 双端，**实际用纯 Vue3 + Vite + TS**。理由：纯 H5 能立刻肉眼验收，数据层已抽成 `repository/storage.ts`，业务逻辑全部平台无关，后续迁 uni-app 只动视图层。已在 README 明确记录这个偏差和迁移成本。

**落地结构**
- `utils/settlement.ts` —— 分摊与结算。金额全程转「分」运算，均分尾差逐个 +1 分抹平；净额 = 已付 − 应担；贪心配对压转账笔数。
- `utils/itinerary.ts` —— 行程生成规则引擎。POI 打分（偏好加权）→ 拆远郊（≤1/3 天数，倒数第 2 天起往前放）→ 地理近邻聚类分天 → 按最近补餐饮 → 按 morning/night 排时间轴。不依赖外部 API Key。
- `data/poi.ts` —— 6 城约 150 个 POI，含真实经纬度。
- `utils/poster.ts` —— Canvas 海报，1080 宽自适应高，布局常量集中定义。
- `stores/trip.ts` —— 唯一 Pinia store，含 `createDemoTrip()` 一键造示例数据。

**验收方式（可复用）**：用 Edge headless + CDP 跑真实流程，注入 `--no-proxy-server` 绕过系统代理（`HTTP_PROXY` 会拦截 localhost 导致 502）。整页截图会让 fixed 元素错位，验证底部栏/键盘/FAB 必须用**视口截图**。

**修复的 3 个真实 bug**
1. 记账键盘用 `grid-row: span 3` + `writing-mode` 排保存键 → 塌成单列。改成 `flex` 外包 + 内部 3×4 grid，保存键固定 92px 贯穿全高。
2. 头像堆叠用 `gap: -6px`（无效值）+ 无 z-index，导致第一个头像被压住。改用 `.avatar-stack` 全局类，负 margin + `nth-child` 递减 z-index。
3. 海报「总支出」行与概览面板重叠，HEADER 高度不足。HEADER 236 → 300 并下移概览面板。

**算法已独立验证**：净额总和为 0、已付总和 == 应担总和 == 账单总额、4 人 3 笔为理论最优、执行转账方案后所有余额归零、方向恒为「应付 → 应收」。`npm run verify`（vue-tsc + build）零错误。
