## 续：在线生成顺路性修复（完成）

入口勘察确认无需改（TripCreatePage 已支持任意城市输入 + inputTips 联想 + 6 城 chips），
但发现顺路性问题：长沙 Day1 排出「岳麓书院 → 5km 外的东方红广场 → 折回旁边的岳麓山」，多绕约 4km。

**根因**：`assemble()` 调 `itemsFromPlan(..., preserveOrder=!!guide)` —— 规则引擎模式
`preserveOrder=false`，聚类好的地理顺路顺序在排时间轴时被「时段权重(morning/night)→duration」
重排打破。在线库 POI 的 `best` 大多是 `any`（toSeed 正则命中不了几个），权重全同时按 duration
升序，恰好把餐饮排到景点前面、景点之间顺序乱掉。

**修法**：`preserveOrder` 恒为 true。`ruleEnginePlan` 内部本来就是「地理近邻逐点 + 餐饮就近插入」
的顺路顺序，直接保留；攻略模式本来就是主题顺序，不受影响。本地 6 城的时段时间由
`slotTime` 起始时间 + duration 推进生成，依然自然呈现早晚节奏。

修后长沙预览（景点顺路、餐饮自然落到傍晚）：
Day1 岳麓书院 → 东方红广场 → 岳麓山 → 佰面郎 → 三食堂炸炸炸

**验证**：amap 17/0、city 41/0、server 313/0、client 137/0、typecheck 0 错、mp-weixin 构建 DONE。

**方法论**：`preserveOrder` 参数名与语义不符（「攻略模式才保留」vs「plan 已排好就别动」），
两个调用方语义不同却共用一个布尔值是本次 bug 的源头。已把调用点语义写进注释。

## 优化清单第三轮：#13 / #2（完成）

### #13 实时通道无发送背压 → 每连接缓冲上限 + 溢出踢线（协议层）

勘察确认是真缺口：`ws.mjs` 的 `rawSend` 直接 `socket.write(buf)`，**完全无视返回值与
`socket.writableLength`**。客户端停止读 TCP（切后台 / 弱网 / 恶意）后，通知帧会无限堆积在
Node 用户态缓冲 —— 内存悄悄涨；且应用层心跳杀不掉它：判活看「对端有没有发帧回来」，
而慢的是「读」方向，对端照样能回 pong。估算放大率：合并窗口 80ms × 单连接 200 订阅 ≈
2500 帧/s × ~150B ≈ 250KB/s，长连接几小时就是 GB 级。

改法（背压是传输问题，归协议层，hub 不动）：
- `ws.mjs`：新增 `DEFAULT_MAX_SEND_BUFFER`（1MB）。检查放 `send()` 而不是 `rawSend` ——
  协议级 ping/pong/close 必须**永远出得去**，连接正是因「发不动」才被踢的，关闭帧再被挡
  就成了强拆（复用 close() 注释里「想关关不掉」的老课）。数据帧才是堆积大头，只对它设限。
  超限 → `onError({reason:'send-buffer-overflow'})` 记账 + `close(1008, 'slow consumer')`；
  通知模型天然自愈（重连后按 rev 重拉，不丢内容）。
- `realtime.mjs`：参数 `maxSendBufferBytes` 透传 + `stats()` 暴露；`index.mjs`：
  `WS_SEND_BUFFER_KB`（默认 1024，0 = 不设限）。

测试（smoke [18]，+8 断言）：假 socket 把「客户端停止读 TCP」变成一个可设的数
（`writableLength` 只涨不消），确定性复现：限内照发 / 超限踢线且留 overflow 记账 /
**关闭帧不受背压限制**（超限踢线后写出的那一帧必须是 CLOSE）/ 踢完后不再收数据帧 /
恰好等于上限放行（严格大于）/ `=0` 显式关闭保护；health 断言确认接线生效。

### #2 多实例脚手架：给 bind() 的设备隔离装上牙（+2 断言）

`bind()` 是所有多设备用例的地基（「A 的读写只落在 A 的存储」），但它自己没断言 ——
改坏交换/还原逻辑后用例只会**偶尔**互相污染（取决于去抖定时器何时触发），绿得看运气。
新增 [0.5] 脚手架自检，一次确定性写入对照钉死三个职责：当前设备是 B 时调
`A.persistSync()` → B 的存储纹丝不动、写入落在 A 的存储、调用完设备必须还原（finally）。
**负对照实测**：把 finally 改成恒还原 'A' → 恰好这一条变红（148/1），其余用例不误伤。

## Bug 修复：结算海报在小程序端生成不出来（完成）

用户反馈「生成海报并不能生成出来」（微信开发者工具 / mp-weixin 端）。

**根因**：`uni.createSelectorQuery()` 默认只查**页面范围**节点，查不进自定义组件内部
（微信文档：「初始时，选择器仅选取页面范围的节点」）。canvas 在 `PosterCanvas` 组件里，
不带 `.in(组件实例)` 在 mp-weixin 端 `select('#posterCanvas')` 永远查空 → `render()` 静默
返回（画布空白）、`save()` 永远「海报尚未就绪」。H5 端 DOM 全局可查所以不炸 —— 典型的
「只在某端复现」的查询作用域坑。

**修法**（PosterCanvas.vue）：
- `scopedQuery()`：`getCurrentInstance()`（setup 顶层取，运行期调会拿到 null）→
  `query.in(instance.proxy)`；`save()` 同样改用。
- 查空不再静默：短重试（120ms × 10 次，覆盖弹层入场动画/首次挂载时机），放弃时
  emit error 提示「海报渲染失败，请重试」而不是留一张空白到底。
- 展示尺寸与内部分辨率分离：canvas 内部恒为 750×H 逻辑像素（×dpr），CSS 尺寸按屏宽
  等比缩小 —— 修掉 750px 画布塞进 480px 弹层被裁剪的问题；导出清晰度不受影响。
- `canvasToTempFilePath` 省略 x/y/width/height：type-2d 导出坐标系有歧义
  （内部尺寸是 cssW*dpr，传逻辑像素会裁掉一部分），缺省即整幅，两端语义一致。
- 卸载时清重试定时器。

## Bug 修复（二轮）：足迹「添加城市」输不了字 —— 三层根因与结构性修复（完成）

第一轮的 dataset 守卫没解决问题。这次用 miniprogram-automator 驱动微信开发者工具做真机级
复现（装了 miniprogram-automator、vue-tsc 进 devDependencies），逐层剥出**三个叠加的独立 bug**：

1. **`inset: 0` 被 WXSS 编译器丢弃** → 遮罩失去定位尺寸 shrink-wrap 成窄条：
   弹层被压成屏幕底部一条 ~240px 窄柱、全屏变暗消失（截图实证）。

2. **uni-app 小程序端 `<Transition>` 重渲染翻车**：弹层打开后任何 setData（打一个字、
   输入框 focus）都把过渡类重置回 enter-from（opacity:0）—— 逻辑树里还在、视觉整层隐身。
   修：弃用 Transition，入场动画改纯 CSS `@keyframes`（插入自动播、重渲染不重播），
   代价是关闭无退场动画。
3. **原生组件穿透 tap 误关弹层（真正的「输入不了」）**：模拟器/非同层渲染下 `<input>`
   不参与 WebView 命中测试，点输入框的 tap 穿透到遮罩本尊 —— `target` 就是遮罩、
   还带着遮罩的 dataset。诊断日志实锤：`target.role === 'mask'`。于是 `.self` 修复、
   dataset 守卫全部无效（穿透 tap 与真背景点击在事件层面无法区分），uni-app 包装事件
   连 changedTouches/clientY 都剥掉了，y 坐标判定也不可行。
   **修（结构性）**：遮罩拆成「backdrop（flex:1）+ sheet（兄弟节点）」—— 两者物理不重叠，
   点弹层内任何东西（含穿透 tap）都到不了 backdrop 的裸 `@click="close"`。零判定逻辑。

**方法论沉淀**：
- 「绿但没测到」的镜像：「测不到但以为测到了」—— dataset 守卫的修复在编译产物层面是对的，
  但没在真实模拟器里点过一次输入框；automator 复现第一次就推翻了它。
- automator `element.tap()` 对 WebView 元素是**直接派发**（不走命中测试），对原生组件才是
  坐标 tap —— 「点背景关闭」这类依赖命中测试的行为没法用它测，别把工具局限当 app bug。
- 反复 `automator.launch` 会把开发者工具楔死（`rawPath` 报错），先全杀进程再冷启动。
- npm install 会清掉 `--no-save` 装的包；实验工具要么进 devDependencies，要么接受丢失。

**验证（automator 端到端）**：开弹层全宽可见（left:16/width:398）→ 点输入框弹层存活且几何
不变 → 打「成都」值与 v-model 同步 → 提交后弹层关闭清空，全链路 PASS。
vue-tsc 0 错；server 323/0；client 149/0；city 41/0；mp-weixin 构建已同步开发者工具。
「点背景关闭」无法用 automator 测（直接派发局限），由结构保证（backdrop 与 sheet 不重叠）。

## #16 双账号（双微信号）端到端验证：行程编辑归属 + 足迹互见

### 自动化验证发现的真 bug
- **现象**：B（第二个微信号）在只读详情页看到「进入编辑」按钮（越权入口）。
- **机制链**：未登录冷启动 → 启动同步 pullAll 匿名 `GET /api/trips`（旧口径「匿名返回全部」）→ A 的行程被并进 B 本地 store → `login()` 不重拉 → TripViewPage `editable = store.trips.some(...)` 误判为可编辑。

### 修复
- **服务端**（db.mjs `listSpaces`）：匿名（viewerOpenid=''）只返回**无主空间**；登录身份仍是「我参与 ∪ 无主」。无主空间（存量数据）保留口径不变，匿名越权口径关闭。
- **客户端**（trip.ts）：抽出 `dropLocalCopy`（纯本地清除，不记墓碑不 commit；removeTrip 复用它）；`login()` 身份变化后 pullAll + 对照 `listSpaces(false)`，清掉「有 revOf（服务端来源）但新身份下不可见」的本地副本（离线拉取失败跳过清理）；同时覆盖「被移出成员」场景。
- **测试口径同步**：smoke [16] 匿名列表断言翻转；client-sync [12]「登出后主动同步仍能读到」更新为「登出后主动同步不再更新有主空间副本」——旧断言编码的正是被关掉的洞。

### 自动化方案要点（scripts/verify-two-users.mjs）
- `mp.mockWxMethod('login', { code })` 把 wx.login 桩成**固定 code** → dev openid = sha1('dev:'+code) 固定 → 身份可复现（等价固定微信号）。
- 会话 C 走真实 UI（退出登录 → 固定 code 登回）换回 A。**不要做 setStorageSync 写身份手术**：活实例的启动同步 / 持久化定时器几秒内就覆盖手写存储，sleep 多久都没用。
- 中断 run 的残留用伪造 dev 令牌清理：`wxs_<openid>.<exp>.<b64url(HMAC_SHA256(SESSION_SECRET,'openid.exp')).slice(0,43)>`。

### 验证结果
- verify-two-users.mjs **30/30 全绿**：A 登录/标足迹/建行程；B 只读浏览（无「进入编辑」、广场剥分享码、空间同步列表隔离）+ 足迹互见 + 归属隔离；C 登回 A 自己行程可编辑 + 互见 B 足迹。
- 回归：server:smoke **340/0**、client:smoke **149/0**、city:smoke **47/0**、typecheck **0 错**。

### 3. 海报 H5 右侧被静默裁掉 40%（本轮最难）

**症状**：标题「成都三日 · 吃与**走**」的「走」、日期尾部不见了。

**排查思路**（先量已知量，别猜）：数据链自相矛盾 —— 组件内读数 `domW:750, sx:1`（刚写的值），
页面实测唯一 canvas 是 `313×737`。两个假设都被证伪：不是「框架事后重置」（手设 750 后跨 6 帧仍是 750）、
也不是「查到不同节点」（全页只有一个 canvas）。

**真因**（读 uni-h5 产物源码定位，文档里没有）：uni 的 `<canvas>` 外壳挂了 ResizeSensor，
布局一变就调内部 `wrapper()`：`canvas.width = offsetWidth × pixelRatio`、
`canvas.height = offsetHeight × pixelRatio`、`ctx.__hidpi__ = true`
（之后所有绘制坐标内部再乘一次 pixelRatio）。
于是我们写 750 → 立刻读回 750 → 算出 scale=1 → 按 750 画进 313 宽的后备存储；
**下一帧** ResizeSensor 把尺寸改回 313（顺带清空）。可见 41.7%，正是观察到的 ~40%。

**修法**（`PosterCanvas.vue` 拆 `renderMp` / `renderH5` 两条路径）：
① 按 `.poster-wrap` **实测宽度**定 displayW/displayH —— 保证画布 CSS 盒子比例 = 海报比例
（原公式 `windowWidth-32` 在桌面 H5 不准：滚动条吃 15px，flex 还会把宽度收缩 328 → 313，
比例一歪画面就纵向拉伸）；② 等两拍让 ResizeSensor 重置完；③ 按盒子实际尺寸推导缩放，
在 **CSS 像素空间**作画；④ 下一拍再验一次尺寸，被改过就重画。全程**不写** `canvas.width/height`。
小程序端不动（`type="2d"` 拿到的是真画布，宽高完全可控）。
实测：盒子 313×704，比例 2.2492 vs 2.248（差 0.05%，纯舍入）。

**顺带修好 H5 的「保存」**：`saveImageToPhotosAlbum` 在 H5 是**未实现**的 API
（就是个 `createUnsupportedAsyncApi`），点了必然失败。改为按逻辑尺寸**离屏重绘** 2 倍图再下载，

## 第五轮（21:2x — 21:3x）：头像初始字的对比度

上一轮把「身份色与分类色重叠」记成待办。这轮**先量再动手**，结论推翻了假设：
真正的问题不是色相重叠，而是**初始字看不清**。

### 1. 实测

头像上的字是 `size × 0.42`（32px 头像 → **13px**），属 WCAG 小字，要 **4.5:1**。
`AppAvatar.vue` 和 `poster.ts` 都写死白字 → 10 个身份色里 **7 个只有 3.18 ~ 3.93:1**
（最差是品牌绿 `#1FA470` 的 3.18:1）。又是「不报错、只是糊」那一类。

### 2. 修法：`avatarInk(底色)` —— 在白/黑里取对比度更高者

不是随手写的 if，它有一条**与底色无关的下界**：
`c白 = 1.05/(Y+0.05)`、`c黑 = (Y+0.05)/0.05`，两者相等时 `(Y+0.05)² = 1.05×0.05`
→ `Y+0.05 = 0.2291` → **两边都是 4.58:1**。所以不管以后塞什么颜色都必然过 AA。
（用 `#1C1C1E` 深灰则下界掉到 4.11，压线不过 → 必须纯黑。）

实测最差 **3.18:1 → 5.34:1，10 个全过 AA**。落地 `AppAvatar.vue` + `poster.ts`，
并加 `check-tokens` ⑤ 号断言防回退。

### 3. 试过并否掉的方案（别重复走）

「把 7 个偏浅的身份色压暗到白字过 AA」看着更保值（白字才是头像常规观感），实测**双输**：
初始字 4.60 ✓，但**两两最挤 17.7 → 11.3 ✗**（压暗把两个蓝 `#1178C9`/`#185FA5` 挤到一起），
且「我」的绿变成 `#008657`，**破坏 `AVATAR_COLORS[0] === --brand`**。
为修对比度牺牲这套色板存在的理由（区分度）不划算 → 改用墨色跟随底色。

### 4. 审计脚本自己漂移过（已修）

`check-palette.mjs` 第一版把「候选色板」写成字面量，色板落地后脚本还停在**旧提案**上 ——
`palette:audit` 报的是一份不存在的色板。已改成**解析 theme.css / format.ts**，
并加 ④ 身份色体检段（墨色对比度、两两距离、离语义/分类最近）。
> 教训：**审计脚本一旦漂移，比没有更糟。** 凡是「校验现状」的脚本，数据必须从源文件解析。

# 第六轮：把「语义色当文字」这一类收干净 + 建对比度闸门

### 1. 上一条 continue 的授权 = 把同一类扫完

第五轮只修了头像一个点。这轮先把全仓 `color: #fff`（10 处）逐个验过，
再做了一次**运行时**全仓文字对比度体检（自写脚本，用 `getComputedStyle` 向上找实际底色，
不是读源码猜），拿到 5 个页面 100 条失败项。分析后归成两类：

- **真缺陷**（代码控制的底色 + 文字，无豁免）→ 修
- **设计取舍**（`--text-tertiary` 的层级、实心按钮白字）→ 用数字定性，记文档不改

### 2. 根因：调色板只有「填充态」，没有「文字态」

| 令牌 | 当文字压白底 | 差多少 |
|---|---|---|
| `--brand` #1FA470 | 3.18:1 | 差 1.32 |
| `--accent` #E8714A | 3.05:1 | 差 1.45 |
| `--warn` #C77E1A | 3.27:1 | 差 1.23 |
| `--danger` #E03B30 | **4.34:1** | **差 0.16** ← 最容易漏的 |

`--danger` 那条最险：它同时当「白底红字」和「白字按钮的底」，**两种角色双向都差一点**。
另外 `.bal-net.plus` 早就用了 `--brand-deep`，而兄弟选择器 `.bal-net.minus` 还在用基色
—— 同一对「应收/应付」一个修了一个没修，这是最典型的「漏一处」。

### 3. 修法：`-deep` 按**最差底色**反推，不按好看挑

三种浅底：白卡 / `--bg-page` / `--bg-subtle`(#E9E9EB)。取最深的 `bg-subtle` 当界：
`Y ≤ 0.14244`（= 0.866/4.5 − 0.05）。这样 -deep 在任何浅底上不必再逐一验。

- `--brand-deep` `#15795A` → `#12724F`（原值压 bg-subtle 只有 4.42，虽说没人这么用，
  但「-deep 在任何浅底上都安全」这条不变式值得是真的）
- 新增 `--accent-deep: #AB3D07`（5.09~6.17）
- 新增 `--warn-deep: #91590A`（4.76~5.77）
- `--danger` `#E03B30` → `#B01F16`（5.67~6.88，双向都过）
  顺带把「餐饮 ↔ 危险红」的 ΔE 从 21.9 抬到 **27.7**，解开了原来正卡在 22 线上的那一对。

### 4. 分类色：**不新增 7 个 `-deep`**，改成结构性限制用途

记账页分类块原来是 `:style="{ background: bg, color: color }"` 挂在**按钮**上，
12px 的标签跟着一起被染色（`--cat-food` 压 `--cat-food-bg` 只有 3.09:1）。

试算过「每个分类也配 `-deep`」并**否掉**：压暗到能过 4.5:1 后，
餐饮的 `#B9470A` 与 `--accent-deep` `#AB3D07` 的 ΔE 只有 **3.9** —— 等于让分类色
变成「应付」的橙，正是这套色板当初（`--cat-ticket == --brand`）要防的事。
暖色带塞不下第二个「深橙」，和「餐饮只能在暖色带」是同一个物理限制。

改成：分类色只挂 `<span class="cat-ic">`（SVG 图标，图形，3:1 线），
标签 `.cat-label` 走 `--text-primary`（13.95:1）。选中态由「浅底 + 图标上色 + 标签变深」三件套表明。

### 5. 闸门自己抓出来、而我手查漏掉的 3 处

| `AppSheet .close-btn` | tertiary 压 bg-subtle **2.25:1**（里面是 SVG 的 ×，连 3:1 图形线都不过） | secondary → 4.69 |

tertiary 压灰底只有 ~2.2:1，那不是禁用，是坏了。

### 6. 海报：品牌带压深 + 去掉半透明白

### 7. 新增闸门 `npm run contrast:audit`（已进 verify 链）

`scripts/check-contrast.mjs`，零依赖，五项：
① 逐条算 `color` + `background` 配对（44 条；实心控件/禁用态按 3:1 记 △）

## 第八轮：地图 callout / label —— 「闸门看不见」的最后一类

第四轮把 CSS 里的颜色收干净了，但 `map` 的 `callout.color` / `label.color` 一直没进闸门：
它们是**运行时 JS 常量**（喂给微信原生 `<map>`，不经过 CSS），① 只读 CSS 规则**看不见**

| 位置 | 原来 | 实测 |
|---|---|---|
| `CityMapPage.vue` `callout` | `color: '#FFFFFF'`，底 `--brand` / `--warn` | 白字 **3.18 / 3.27:1**；而 `content` 是 **12px 城市名**（正文要 4.5） |

### 新闸门 ⑥

（编号取 ⑥ 而不是插在中间，是为了不改动已被多处引用的「第五节」—— 编号本身也是快照。）

2. `avatarInk` 对 `CANVAS_PALETTE` 全部 **13** 个底色都 ≥ 4.5:1（最差 `textSecondary` #66666E → 5.69:1）。
3. **结构断言**：`avatarInk` 的函数体里必须同时出现黑与白两个返回值、且基于 `relLuminance(bg)`。

### ⚠️ 本轮最重要的收获：闸门必须被证伪过一次

⑥ 的第一版只有第 1、2 条。做证伪测试时把 `avatarInk` 的实现改成 `return '#FFFFFF'`

1. **静态闸门和运行时体检互相看不见对方那半边** —— 改完颜色两个都要跑。

## 第十轮：属性里的颜色 + 旧色值的「第二种拼写」

第九轮是「运行时反过来喂静态闸门」；这一轮把喂进来的固化成断言，并问
**「还有什么写法是这个闸门读不到的」** —— 又扫出两层，都不是靠体检。

### 1) `<AppIcon color="…">` 是**属性**，① 和 ② 都读不到

全仓：`var(--brand)` ×11、`var(--danger)` ×3、`var(--text-tertiary)` ×18、`#fff` ×6，一条没被读过。
更值得记的是：② 的允许清单 `ICON_ALLOW = ['.nav-icon']` 是**照着 CSS 写法拟的**，
而图标色的真实来源是模板属性 —— **清单在守一个几乎不存在的地方**。

顺手量出的真话（② 说「图形只要 3:1」在本项目站不住）：

| 图标色 | 白卡 | 页面底 | bg-subtle | 自己的 -soft |
|---|---|---|---|---|
| `--brand` | 3.18 | **2.85** | **2.62** | `--brand-soft` **2.82** |
| `--text-tertiary` | **2.73** | **2.45** | **2.25** | — |
| `--brand-deep` | 5.92 | 5.31 | 4.88 | — |
| `--danger` | 6.88 | 6.16 | 5.67 | `--danger-soft` 6.01 |

`.nav-icon`（底=页面底）2.85、`.tool-icon`（底=`--brand-soft`）2.82 —— **有意保留**
（压成 `-deep` 会丢掉「绿色 = 可点」这个视觉语言，Apple 自家 tint 图标也在 3:1 附近），
但**不能写成达标**。已把 ② 的注释改成实话，并新增闸门 **⑧**（`contrast:audit`）：
裸色值（`#fff` 除外）✗、`var()` 指向不存在的令牌 ✗，其余按图形 3:1 打印实测值 × 使用次数。

> ⚠️ **⑧ 差点又是假闸门**：第一版把裸 hex 落进了 `dynamic`（「动态表达式，静态算不了」）分支，
> 直接放过 —— 断言声称拒裸色值，实际一个都拒不了。**是证伪时发现的**：
> 故意把 `color="var(--brand)"` 改成 `#1FA470`，它照样全绿。
> 判据要写细：`/^#[0-9A-Fa-f]{3,8}$/` 才是裸色值，`c.color` 这种标识符才算动态。

### 2) 同一个旧色值有**第二种拼写**

④ 只认十六进制 → 旧米色 `#F8F7F4` 以 `rgba(248, 247, 244, 0)` 活在**三处滚动渐变的透明端**：

```css
background: linear-gradient(to top, var(--bg-page) 72%, rgba(248, 247, 244, 0));
```

肉眼看不出（两端都是近白），但它是旧视觉残留，而且**十六进制搜索永远扫不到**。
给 ④ 加上分量形式正则后**当场报出 3 处**（先加扫描、后修 —— 这次证伪是天然的，红→绿）。
同时把旧 `--brand-deep` `#15795A` 也加进 DEAD（和 `#1D9E75` 同性质：**「另一个绿」**）。

**教训**：一个「搜旧色值」的检查必须覆盖**所有等价写法**（hex / rgb() / rgba() / 8 位 hex），
否则它守的是拼写而不是颜色。

### 3) 海报里最后的手写色 + 一个令牌两个角色

- `poster.ts` 4 处 `ctx.fillStyle = '#FFFFFF'`（值上等于 `bgCard`）→ 全走 `P.xxx`；
  新增断言「此文件不许出现手写颜色字面量」。**「恰好相等」不是理由，唯一来源才是。**
- 品牌带 5 处白字原来借 `P.bgCard`（**卡片底**的角色）→ 新增 `textInverse`(`--text-inverse`)，
  ⑥ 断言「不许借 `bgCard` 当白字」。**与 CSS 的 `--line-strong` 是同一类错误：一个令牌担两个角色。**
- `poster.ts` 注释「brandDeep `#15795A` → 白字 5.37:1」**值和结论双错**
  （现令牌 `#12724F`，5.92:1）→ 按规矩改成「别在这儿写数字」。

### 验证

```
verify           EXIT=0（check:tokens 8 项 · contrast:audit 45 条配对 + 七类断言
                 · build:mp-weixin DONE · wxss:lint 22/22 · city 56/0）
build:h5         DONE
npm test         server 340 · client 149 · city 56 · amap 17 —— 全部 0 失败
证伪             ④ 分量形式（天然红→绿 3 处）· ⑥ 手写字面量（✗8）· ⑥ 借 bgCard（✗1）
                 · ⑧ 裸色值（✗2，退出码 1）；全部恢复后复跑通过
```

### 可复用小结

1. **「闸门读不到的写法」本身就是一层盲区**：属性（props）、`rgb()` 拼写、另一个合法令牌的
   角色借用 —— 都和「颜色没进 CSS」同源。每加一条断言，都问一句「它读的是哪个写法？」
2. **写断言时判据要写细**，别给自己留「动态表达式」这种万能豁免口 —— 那正是漏掉裸色值的地方。
3. **一个令牌只担一个角色**：底色 / 文字 / 线，各归各的令牌，哪怕当前值完全相同。

## 第十一轮：色板约束终于有闸门了；以及一个横跨三个脚本的假绿灯

`palette:audit` 一直只打印、不判定、也不在链里 —— 于是「分类色的三条约束」从来没有保护。
补判定（22 / 20 / 3.0:1）时我在脚本里写了「已进 verify 链」，可 `package.json` 还没改；
**先改链再跑**，不留下「话与事实不符」。

### 1) 换问法：这个闸门读的是**哪一种写法**？

`check-palette.mjs` 用 `/(--[a-z0-9-]+)\s*:\s*(#[0-9A-Fa-f]{3,8})/g` 解析 theme.css，只认十六进制；
而分类色是 `VARS['--cat-food'] || '#000000'` **带回退**的。实测把 `--cat-food` 写成
`rgb(232, 89, 12)`（**＝ `#E8590C`，视觉一模一样**）：

```
餐饮  #000000 (h0)   ← 回退成纯黑
✓ 分类色 vs 语义色 ΔE：38.5（真实 23.5）
✓ 压同色浅底对比度：3.31:1（真实 3.09）
EXIT=0
```

**三项数字全部变好看**（黑离谁都远）→ 真实越界被这份「更好的报告」盖住。
这比漏检更坏：漏检只是没发现，这是**主动给出更好看的错数**。

### 2) 同一份正则，在对比度闸门里是另一种静默

`check-contrast.mjs` 有同一份 hex 正则，但失败姿态不同：`if (!bg || !fg) continue` 直接**丢掉这一对**，
而断言写的是「**已参检的**配对全部达标」。实测 `--text-primary: rgb(28, 28, 30)`：

```
✓ 37 条「color + background」配对全部达标      ← 原本 45 条
对比度闸门通过 …                                EXIT=0
```

8 条凭空消失，而 `--text-primary` 是**正文墨色主令牌** —— 消失的恰好是正文那批配对。
**而且这是撞运气**：52 个令牌里只有 6 个被 `TOKENS['--x']` 直接解引用（会抛
`TypeError: Cannot read properties of undefined`，退出码非 0 但诊断为零，堆栈指向 `hex.replace`），
另外 **46 个换写法就是干净的假绿灯**。

### 3) 修法：一份共用解析 + 解析覆盖率硬失败

抽 `scripts/lib/theme-tokens.mjs`，三个闸门共用（同一份 hex 正则原来各写一遍 —— 这是
「审计脚本各漂各的」这个隐患的**第三次现身**，前两次是历史基线快照和 SEMANTIC 字面量快照）。

- 松扫描（所有 `--x: 值;`）÷ 紧解析（只收 hex）做差；
- **不透明**的差集（`rgb()` / `hsl()` / 色名）→ **硬失败**；
- **带 alpha** 的差集 → 放行但记账（`--hairline` 的 alpha 本身是信息）；
- 另加 `assertRequired` 令牌依赖清单 —— 防的是**令牌被整个删掉**（那时文件里连声明都没有，
  松扫描天然抓不到；注意「引用还在」不等于「声明还在」）。

**坑**：`HAS_ALPHA` 第一版写成 `/^rgba?\([^)]*,\s*[\d.]+\s*\)$/`，而 `rgb(102,102,110)` **也匹配**
（贪婪回退）→ 「带 alpha 所以放行」这条豁免会把要治的病原样放过。必须**要求第 4 个分量**。

另外两条可见性：① 报告头打解析覆盖率行；① 把「有 color+background 但解析不出实色」的规则逐条列出
（以前是无声 `continue`，这是配对数缩水的唯一路径）。实测立刻印出 3 条。

### 4) 证伪四次

| # | 动作 | 实测 |
|---|---|---|
| 1 | `--cat-food` 改 rgb() | 修前 EXIT=0（假绿）→ 修后 ✗ EXIT=1 |
| 2 | `--text-primary` 改 rgb() | 修前 EXIT=0 → 修后**三个闸门**都 ✗ EXIT=1 |
| 3 | 删 `--text-secondary` 的声明（引用还在） | 依赖清单拦下 ✗ EXIT=1 |
| 4 | 全部恢复 | EXIT=0 ×3，覆盖率行正常 |

### 5) 顺手清掉四个过期数字

README「后端 313 / 客户端 137 / 城市 41 条断言」（实为 **340 / 149 / 56**）、「tertiary 70 处」（实为 72）
→ 全改「以脚本输出为准」。其中「70 处」那句本已写了「不写死」，却在同一括号里补了数字
—— **规则和例外在同一个括号里打架，等于没有规则**。

### 验证

```

                 → build:mp-weixin → wxss:lint → city:smoke）

build:h5         DONE；npm test  server 340 · client 149 · city 56 · amap 17 —— 0 失败
```

### 可复用小结

1. **「解析不到的时候，它做了什么？」** 回退默认值 / 跳过 / 抛异常，三种都是静默或不可诊断，
   而**回退默认值最坏**（数字会变好看）。凡是「解析 → 计算 → 断言」的脚本，都要在解析层先问这一句。
2. **断言写「已参检的都达标」时，必须同时盯住「参检数量」** —— 缩水是它唯一能悄悄放水的路径。
3. **两份同样的解析 = 两次漂移**：审计脚本的输入口径也应该只有一个来源。
4. **规则旁边别放例外**：写了「以脚本输出为准」就不要再补具体数字。

## 第十二轮：「我的攻略」管理页（按 openid 聚合）—— 完成

「下一步可选」里唯一纯前端且接口已就绪的一项。交付：`MyGuidesPage`（入口在「我的 → 行程工具」）、
store 新动作 `fetchMyCloud()` / `deleteCloudGuide(id)`、city smoke +9 条（56 → 65）。

### 页面语义

- **与「城市足迹」页的分工**：那页管**本机**（编辑、地图标点），这页管**云端到底存了什么**
  （跨设备、含改昵称留下的旧行）。数据源 `/api/my/guides`（服务端按 openid 归属过滤）。
- 三个空态分开：未启用云同步 / 未登录 / 拉取失败各有文案与出口。**未登录绝不能显示成
  「云端还没有记录」**—— 所以 `fetchMyCloud` 失败要**抛错**，静默返回 `[]` 会把原因说成结果。
- **「对不上的」差异区**（本页真正要让人看见的东西）：
  · 本机有、云端没有 → 补发。`publishMyGuide` 内部自吞错误，所以补发完**再拉一次确认**；
  · 云端有、本机没有 → 并入本机（`syncMine`）。
- 重复行：服务端按 (城市, 昵称) upsert，**改昵称会留下旧行**；按 **id** 逐条撤回
  （`retractMyGuide(name)` 按 (城市, 当前作者) 删，恰好删不到旧行——这正是本页存在的理由之一）。

### 测试里抓到的假绿（自己先栽了一次）

越权断言「B 删 A 的记录要 403」第一版跑出来 **200**：`sessionTokenOf()` 从**当前设备**的
存储现取令牌，测试里 `as('A')` 之后当前设备还是 A —— B 的删除实际带的是 **A 的令牌**，
服务端当然放行。修法：断言前 `as('B')`。教训：**测试替身里的「当前上下文」是全局的，
凡依赖它的取值都要显式切换**，否则测的是替身的状态而不是被测代码。

### 证伪

「未登录抛错」：把 `throw new Error('尚未登录')` 临时改成 `return []` → 断言变红 → 恢复复跑 65/0。

### 视觉走查（H5 真浏览器）

后端要 `ALLOWED_ORIGINS='*'`（默认空 = 不回 CORS 头，H5 全部 request:fail 且表现为「拉取失败」）；
dev 登录 + localStorage 注入 `travel_sync_v1.identity`；端到端核对：空态 / 列表（含「多条」组）/
差异区补发（云端 4→5）/ 确认弹层撤回（5→4）/ 「我的」页入口跳转。截图在 `shots-ios/MyGuidesPage*.png`。

### 可复用小结

1. **「从别的设备/页面回来」的页面用 `onShow` 重拉**，`onLoad` 里不用再拉一次（首次进入
   onShow 紧跟 onLoad）。
2. **清单类页面的价值常在「差集」而不在「清单」**：两边数据（本机 vs 云端）各看一遍都会
   觉得没问题，差集摆出来才知道哪次发布没成功。
3. 另：AppNav 的 `.nav-icon` 是 scoped 样式，插槽内容吃不到 —— 用右插槽时别指望它。
