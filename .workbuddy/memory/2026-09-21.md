## 全国城市生成修复（commit 3c2d8e2）

用户反馈「行程还是只有几个城市」。实测排查（大理/喀什/洛阳）结论：**在线生成的代码链路早已接通（高德 key 有效），但三个体验问题让它看起来像「没上线」**：

1. **联想永远不出候选（根因最深）**：高德对城市名必返回一条区划候选（如「云南省大理白族自治州大理市」），其 `location` 字段是**空数组 `[]`** 而不是字符串——`loc.split` 直接 TypeError，整个联想结果崩成空。修法：`parseLngLat` 加类型守卫（只接 `{lng,lat}` 对象或 "lng,lat" 字符串），并修正 filter（空 location 的候选该跳过而不是炸掉整轮）。**教训：外部 API 同名字段在不同类型候选上形态分裂，类型守卫不能只防 null**。
2. **限流失败静默回退成都（最误导）**：生成一次要 6 路并发检索，高德个人 key QPS 限额下第二轮实测就失败；失败后 `matchCity` 兜底**静默返回 CITIES[0]（成都）**——用户要洛阳，拿到一份成都行程，自然认为「洛阳没上线」。修法：并发压到 2 路 + 限流退避重试 + 城市级内存缓存 + 整体二次重试；非库城市抓取失败**明确报错**（生成页显示具体原因），彻底删除静默回退。**教训：失败伪装成「数据不对」比失败本身更伤——兜底不能吞掉失败语义**。
3. **点联想候选目的地变脏串**：inputtips 的 `district` 是完整区划串「云南省大理白族自治州大理市」。修法：候选带 adcode → district 接口反查标准城市名（实测「大理站」→「大理市」）。UI 顺手：生成页显示「正在拉取 XX 的高德点位」；创建页城市区加「热门城市」标题。

端到端实测：大理/喀什/洛阳/长沙连续生成全绿（修复前第二轮就限流回退）。回归：client:smoke 237/0（+5 parseLngLat 断言）、typecheck 0 错、verify EXIT=0。
